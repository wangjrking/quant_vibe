# MCP 资产网关中台方案

## 当前定位

本文档定义本项目当前阶段的 L8 MCP 资产发布层方案。目标不是建设远程全量数据中心，也不是迁移 L1-L7 大表，也不是由 MCP 智能体发布 L7 资产，而是把已经由专业智能体生产、经审计放行、允许作为来源引用的材料，重新登记为 L8 发布资产后，通过 MCP 中台对外提供受控访问。

当前主线技术栈：

```text
PostgreSQL + MinIO/对象存储 + MCP gateway
```

第一阶段不引入 ClickHouse；旧远程数仓、ClickHouse 全量迁移、远程计算预测和远程全量数据中心方案已降级为历史方案。

## 负责智能体

负责人：MCP智能体（`mcp-agent`）。

历史名称 `data-warehouse-agent` 已废弃，不再作为正式智能体、平台入口或职责归口。旧名称只作为迁移来源和历史兼容说明保留。

## L8 职责边界

MCP智能体负责：

- MCP 中台架构。
- 对外资产网关。
- PostgreSQL registry、manifest、audit、权限、发布状态和服务目录。
- MinIO/对象存储目录、归档、快照和生命周期规则。
- MCP 接口契约。
- 部署包演进和服务器执行指导。
- L8 发布资产的接入、索引、授权和回滚口径。
- L5/L6/L7 已审计材料作为 L8 发布资产来源证据时的引用口径。

MCP智能体不负责：

- 不补 L1 原始数据。
- 不构建 L2 综合底表。
- 不计算 L3 因子或标签。
- 不训练 L4 模型，不生成预测。
- 不生成 L5/L6 策略信号，不跑回测。
- 不生成交易建议、下单价格或下单时间。
- 不迁移、覆盖、删除生产资产。
- 不擅自切换任何 L1-L7 主线默认入口。

## 第一阶段发布资产范围

第一阶段只发布 L8 资产。L5/L6/L7 产物只能作为 L8 资产的来源证据或引用来源，不能以原层级资产身份由 MCP 智能体发布。

第一阶段 L8 资产类型：

- 策略展示资产。
- 信号展示资产。
- 效果展示资产。
- 审计展示资产。
- 交付说明资产。
- 发布状态资产。

后续可以引用 L5/L6/L7 已审计来源材料，但必须满足：

- 资产已有明确 owner。
- 资产有显式 manifest。
- 资产已完成审计智能体复核。
- 资产允许作为 L8 发布资产来源。
- 资产有回滚或下线方案。

## 存储边界

### PostgreSQL

PostgreSQL 只保存治理和索引数据：

- asset registry。
- manifest 索引。
- audit 记录。
- 权限、角色和访问策略。
- 发布状态。
- 服务目录。
- lineage 和回滚指针。
- MCP 请求审计日志。

PostgreSQL 不作为 L1-L7 大表计算库，不承接全量行情、因子矩阵或预测明细的大规模计算。

### MinIO/对象存储

对象存储保存可发布文件：

- L8 策略展示文档。
- L8 信号展示文件。
- L8 策略效果展示报告。
- 回测报告。
- 归档包。
- 快照文件。
- 可发布证据文件。

对象存储路径必须区分生产发布和实验发布。

```text
published/production/
published/experimental/
archive/
snapshots/
audit-evidence/
```

### MCP gateway

MCP gateway 只提供受控读取和治理查询接口：

- 查询 L8 发布资产列表。
- 查询策略展示资产。
- 查询信号展示资产。
- 查询效果展示资产。
- 查询审计状态。
- 查询 manifest 和发布状态。

MCP gateway 不直接触发训练、预测、回测、交易或 L1-L7 数据加工。

## 审计与审批

进入生产发布前必须满足：

1. 专业智能体完成资产生产并提交显式 manifest。
2. 审计智能体完成只读复核。
3. 指挥官智能体确认工作流闭环。
4. 主人批准生产发布、权限开放或服务上线。

未完成审计的资产只能进入实验发布区，不能进入生产发布区，不能作为对外默认结果。

## 后续交接给 MCP智能体的工作

MCP智能体后续应继续完成：

- 旧文档降级说明。
- 部署包语义重命名。
- L8 PostgreSQL schema。
- 对象存储发布目录规范。
- 只读资产扫描和发布候选清单。
- MCP gateway skeleton。
- 健康检查、权限检查和审计日志模板。

这些动作不得触发 L1-L7 生产加工，不得迁移、覆盖或删除生产资产。
